6. 把下面这段【原样、有 bug 的】代码整段粘进去：

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[i]); j += 1   # 此处存在缺陷
    return result + left[i:] + right[j:]


def merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    return merge(merge_sort(a[:m]), merge_sort(a[m:]))


print(merge_sort([3, 1, 4, 1, 5, 9, 2, 6]))

7. 运行：右键编辑器空白处 →「运行 'merge_sort'」（或菜单 运行 → 运行，快捷键 Shift+F10）
8. 下方「运行」窗口会输出：

[1, 5, 4, 3, 4, 5, 6, 9]

   而正确排序应该是 [1, 1, 2, 3, 4, 4, 5, 6, 9]。
   所以结果是乱的 —— 这就确认了「结果错误」。

   ✅ 截图点 1：运行窗口里这个乱序输出 [1, 5, 4, 3, 4, 5, 6, 9]

9. 设断点：把鼠标移到下面这行【行号右边的空白处】，点一下，出现红色圆点：

        else:
            result.append(right[i]); j += 1   # 此处存在缺陷

   （断点设在 else: 这一行，也就是第 9 步里这行的行号右边）

10. 启动调试：右键编辑器空白处 →「调试 'merge_sort'」（或菜单 运行 → 调试，快捷键 Shift+F9）
    程序会停在你设断点的地方，那一行变成蓝色高亮。

11. 看变量：下方「调试器」窗口，左边「变量」（Variables）面板里能看到：
      i、j、left、right 以及它们的值。

12. 单步走：按 F8（单步跳过）一行一行往下走，每走一步看一次 i 和 j。

    你要找的是「i 和 j 不相等、但代码却用 right[i]」的那一刻，典型情况：

    当 left = [1, 3]、right = [1, 4] 时，某次断点停住：
      i = 1        j = 0
      left[i] = left[1] = 3
      right[j] = right[0] = 1
    因为 3 > 1，程序走 else，本应取 right[j]（=1），
    但代码写的是 right[i]（=right[1]=4），所以取错了。

   这就是 bug 的根源：i 是左指针，j 是右指针，else 里应该用 right[j]。

   ✅ 截图点 2：断点停住时，「变量」面板里 i、j、left、right 的值
     （最好能拍到 i=1、j=0 这种 i 和 j 不一样的情况）

───────────────────────────────────────────────
【第 3 步】最小修复，重新运行

13. 把 else 那一行的 right[i] 改成 right[j]（只改这一个字母）：

        else:
            result.append(right[j]); j += 1   # 已修复

from merge_sort import merge_sort


def test_given_input():
    assert merge_sort([3, 1, 4, 1, 5, 9, 2, 6]) == [1, 1, 2, 3, 4, 4, 5, 6, 9]


def test_duplicates():
    assert merge_sort([5, 3, 5, 1, 3, 1]) == [1, 1, 3, 3, 5, 5]
