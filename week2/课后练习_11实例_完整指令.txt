  只留最容易完成、最容易截图的调试 / IDE / LLM / 网页 + 可靠的 Linux 命令行实例。

实例 1：ls 组合选项（参数与 Globs）
═══════════════════════════════════════════════════
环境：Windows Git Bash 或 Ubuntu 虚拟机（GNU ls）
1. 打开终端，敲一条命令，一次满足「含所有文件、易读大小、按时间排序、带颜色」：
       ls -laht --color=auto
   各选项含义：
     -l           长格式（权限 / 大小 / 时间 / 名字）
     -a           包含所有文件，包括 . 开头的隐藏文件
     -h           大小易读（如 1.1M、454M，而不是纯字节数）
     -t           按最近修改时间排序
     --color=auto 输出带颜色
2. 观察输出，和题目给的示例对比（大小是 1.1M、106M 这种，不是 454279954）

实例 2：配置语言服务器，对「库依赖」跳转到定义
═══════════════════════════════════════════════════
环境：Windows · PyCharm
1. PyCharm 里新建一个 Python 文件，写这两行：
       import random
       print(random.choice([1, 2, 3]))
2. 把光标放到 choice 这个词上，按 Ctrl+B（或按住 Ctrl 点鼠标）
3. 会跳到标准库 random.py（或类型存根 .pyi）里 def choice(...) 那一行，
   这就是「对库依赖跳转定义」成功（第 6 题跳的是自己写的函数，这题跳的是标准库）。
截图 1~2 张：
  ① 代码里光标放在 choice 上
  ② 跳转后打开的标准库 def choice 定义页

实例 5：排查端口被占用，找到进程并结束它
═══════════════════════════════════════════════════
环境：Windows（Python 已装）
1. 开两个终端窗口（开始菜单搜「命令提示符」cmd，或 PowerShell，开两个）
2. 终端 A 敲：
       python -m http.server 4444
   （会一直运行、别关，这就是那个「占用 4444 端口的最小 web 服务器」）
3. 终端 B 敲（PowerShell 用第一句，cmd 用第二句）：
       netstat -ano | Select-String 4444
       netstat -ano | findstr 4444
   找到「本地地址 0.0.0.0:4444」那一行，最后一列数字就是 PID（例如 12345）
4. 终端 B 敲（换成你查到的 PID）：
       taskkill /PID 12345 /F
5. 回到终端 A，会看到服务已被结束。
截图 1~2 张：
  ① 终端 A 的 python -m http.server 已启动
  ② 终端 B 的 netstat 查到 PID + taskkill 结束进程

实例 7：touch -- -myfile，再不用 -- 删除它（参数与 Globs）
═══════════════════════════════════════════════════
环境：Windows Git Bash 或 Ubuntu 虚拟机
1. 创建一个以 - 开头的文件（-- 告诉 touch：后面是文件名，不是选项）：
       touch -- -myfile
2. 确认建好了（能看到一个叫 -myfile 的文件）：
       ls -la
3. 不用 -- 把它删掉：文件名以 - 开头，直接 rm -myfile 会被当成选项，
   所以在文件名前面加 ./ 前缀：
       rm ./-myfile
4. 再用 ls -la 确认已经删掉了
截图 1~2 张：
  ① touch -- -myfile 建文件 + ls -la 能看到 -myfile
  ② rm ./-myfile 删除 + ls -la 确认消失

实例 8：用 strace 跟踪系统调用（需虚拟机）
═══════════════════════════════════════════════════
环境：Ubuntu 虚拟机（先开机，直接在虚拟机桌面开终端）
1. 安装（如已装会提示「已是最新版本」）：
       sudo apt install -y strace
2. 跟踪一个简单命令：
       strace ls -l
   观察输出：里面是一堆系统调用，常见的有
   openat（打开）、fstat（查文件信息）、getdents64（读目录）、
   read / write（读写）、close（关闭）等
3. 可选：跟踪一个更复杂的程序，看它打开了哪些文件：
       strace python3 -c "print('hi')"
截图 1~2 张：
  ① strace ls -l 的输出（能看到一堆系统调用）
  ②（可选）更复杂程序的 strace 输出

实例 9：进程替换 —— 用 diff 比较 printenv 与 export
═══════════════════════════════════════════════════
环境：Windows Git Bash 或 Ubuntu 虚拟机（bash）
1. 敲一条命令（<(命令) 是进程替换，把命令的输出当成一个「临时文件」传给 diff）：
       diff <(printenv | sort) <(export | sort)
2. 观察：diff 会显示两边的差异（几乎每一行都不同）
3. 为什么不一样？printenv 输出的是 NAME=value 这种纯格式；
   而 bash 里的 export 输出的是 declare -x NAME="value"，带 declare -x 前缀和引号。
   所以变量集合其实基本一样，只是输出格式不同，diff 就认为它们不同了。
截图 1 张：
  ① 执行 diff <(printenv | sort) <(export | sort) 的输出（能看到两边的格式差异）

实例 10：用 hyperfine 基准对比两个实现（需虚拟机）
═══════════════════════════════════════════════════
环境：Ubuntu 虚拟机
1. 安装：
       sudo apt install -y hyperfine ripgrep fd-find
2. 到一个目录（比如 home），对比「find」和「fd」两种列文件方式：
       cd ~
       hyperfine 'find . -type f' 'fdfind --type f'
   （注意 Ubuntu 里 fd 的命令名叫 fdfind）
3. 看结果：hyperfine 会对每个命令自动跑多遍，给出 均值±标准差 和 速度倍数
截图 1~2 张：
  ① hyperfine 安装完成
  ② hyperfine 输出结果（对比表 + 倍数）

实例 11：用 htop 监控系统（需虚拟机）
═══════════════════════════════════════════════════
环境：Ubuntu 虚拟机
1. 安装：
       sudo apt install -y htop
2. 终端 1 敲（占满一个 CPU 核，跑着别停）：
       python3 -c "while True: pass"
3. 终端 2 敲：
       htop
   看到 python3 占 CPU 接近 100%；按 q 退出 htop
4. 结束：回到终端 1 按 Ctrl+C
   （进阶可选：taskset --cpu-list 0,2 stress -c 3 需要先 sudo apt install stress，
    且虚拟机要有 ≥3 个核；核不够会报错，可跳过）
截图 1~2 张：
  ① 终端 1 的 python3 占用程序在跑
  ② htop 界面显示 CPU 高占用
